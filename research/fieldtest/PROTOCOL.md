# 测量方案：公开代理列表与免费节点的 72 小时实测

第一阶段 1B。版本 1，2026-11-05。

这份方案在取数之前写定。指标的定义、判定规则和预期范围都先写在这里，数据出来以后不改口径；
确实要改时记在文末的变更记录里，并说明原因。

## 要回答的问题

每个问题都对应一项设计决定。回答不了设计问题的数据不采。

| 问题 | 对应的设计决定 |
| --- | --- |
| 公开列表里的条目有多少能当代理用，各来源差多少 | 默认启用哪些来源，来源怎样降权 |
| 能用的代理能用多久 | 粘性会话的时限，复测的频率 |
| 列表更新得是否及时：上榜时还活着吗，死了多久才下榜，下榜的是不是其实还活着 | 以列表为准还是以实测为准 |
| 列表给的协议标签准不准 | 协议是否必须以握手实测为准 |
| 多少代理会改明文内容、冒充 TLS、改请求头、带出客户端地址、重放请求 | 不可信层默认只承载端到端 TLS 是否必要 |
| 出口地址与入口是否相同，是否稳定，不同目的地看到的是否一致 | 粘性会话绑定“实测出口地址”是否成立 |
| 免费节点有多少可用，严格校验证书会损失多少 | 要求跳过证书校验的节点默认不可用，代价有多大 |
| 聚合器独有的条目有多少可用 | 聚合器默认关闭是否合理 |

## 测量对象

- 14 个常规列表，全部条目都探测。
- 4 个聚合器，每个只从“不在任何常规列表里”的条目中随机抽 5,000 条探测（不足 5,000 条的全取）。
  抽样只做一次，种子和抽中的条目都记在快照记录里。
- 11 个节点订阅里的 ss、vmess、vless、trojan 节点。

来源清单在 `internal/lists/sources.json`，与第一阶段普查用的是同一批。
只接触出现在这些公开列表里的地址，不做任何扫描。

## 组成

| 部件 | 作用 |
| --- | --- |
| judge | 目标站点，同时是独立的见证方。HTTP 和 HTTPS 各一个端口，返回固定哈希的载荷，把自己实际收到的东西记下来 |
| 快照采集器 | 每 10 分钟抓一次各列表，记下增减的条目；订阅每 30 分钟抓一次 |
| 探测器 | 对每个条目按阶段探测，记下每一条连接的结果 |
| sing-box 1.14.4 | 官方发布的程序，不改动。节点探测时作为本机的旁路进程使用 |

judge 和探测器是两个进程、两份日志。这一轮只有一台服务器，两者同机，见“已知局限”。

## 一次尝试

一次尝试是一条连接，从建立到关闭按阶段推进。每个阶段要么通过，要么归到一个固定的失败类别，后面的阶段不再进行。

1. TCP：连到代理的地址。
2. 握手：按被测的协议说话。SOCKS5、SOCKS4、HTTP CONNECT 请求连到 judge；HTTP 转发没有这一步。
3. TLS：在隧道里与 judge 握手。证书校验始终开启，另外要求叶子证书的公钥就是 judge 的那一把。
   校验不过就中止，不发送任何数据，并把对方给出的证书链留作证据。
4. HTTP：请求 `/p/<种类>/<nonce>`。nonce 每次不同，带签名和签发时间。
5. 核对：状态码 200；正文的 SHA-256 等于期望值；响应头里的金丝雀与 nonce 相符。
   正文不符时保存收到的正文作为证据。

载荷有三种：一张 HTML 诱饵页面（有脚本、表单、iframe、仿常见广告网络写法的广告位、8 个 https 链接）、
一段 JavaScript、32 KB 不可压缩的二进制。内容只由 judge 的主机名决定，任何人都能算出期望的哈希。

失败类别：

| 阶段 | 类别 |
| --- | --- |
| TCP | `tcp_timeout` `tcp_refused` `tcp_unreach` `tcp_reset` `tcp_other` |
| 握手 | `hs_timeout` `hs_eof` `hs_reset` `hs_not_proto`（对方说的不是这个协议，记下它发来的头几十个字节）`hs_auth`（要求认证）`hs_refused`（协议层面的拒绝，带代码）`hs_violation` |
| TLS | `tls_cert_invalid`（证书不是 judge 的）`tls_pin_mismatch` `tls_not_tls`（隧道另一头不是 TLS）`tls_alert` `tls_timeout` `tls_eof` `tls_reset` |
| HTTP | `http_timeout` `http_eof` `http_reset` `http_malformed` `http_status`（非 200）`http_body_mismatch` `http_canary_missing` `http_canary_bad` |

遇到要求认证的代理，记录下来就停，从不尝试任何凭据。

## 一次探访

一次探访是对同一个条目连续做的一组尝试。

- 完整识别：条目第一次连得上时，以及此后每 24 小时一次，把 SOCKS5、HTTP CONNECT、HTTP 转发、SOCKS4 四种协议都试一遍，先试列表标签声称的那种。第一条连接就连不上时不再试其余协议。
- 平时：只试上一次通过校验的那几种协议。
- 附加测试（每 6 小时一次，只对可用的条目）：
  经隧道访问两个公开的 IP 回显服务，看它们看到的出口地址；在 SOCKS 隧道里走一次明文 HTTP；
  对 HTTP 转发再取一次 JavaScript 和二进制载荷。
- 完整识别时另外做两项：让 CONNECT 连 judge 的 80 端口，看代理的端口策略；
  对标签是 https 的条目，看代理端口本身是否说 TLS（只握手，不发数据）。

## 指标定义

| 指标 | 定义 |
| --- | --- |
| 连得上 | 至少一次尝试的 TCP 阶段通过 |
| 有协议回应 | 至少一次尝试得到协议层面的回答，包括拒绝和要求认证。对应 Mani 等的 responsive |
| 可用 | 一次探访里至少有一次尝试走完全部阶段并通过核对 |
| 时点可用率 | 某一时刻在榜的条目里，最近一次探访可用的比例 |
| 累计可用率 | 探访过的条目里，至少可用过一次的比例 |
| 寿命 | 从第一次可用，到其后连续两次探访都不可用的第一次。观察结束时仍可用的按右删失处理，用 Kaplan–Meier 估计。分辨率是探访间隔（20 分钟） |
| 上榜新鲜度 | 新上榜的条目在第一次探访（上榜后约 10 分钟内）即可用的比例 |
| 下榜滞后 | 最后一次可用到下榜之间的时间；下榜后 24 小时内仍可用的比例 |
| 标签准确率 | 标签声称的协议里实测可用的比例，并给出标签与实测的对照表 |
| 内容被改 | 明文响应状态 200 而正文哈希不符。分三种：截断（收到的是期望正文的前一段）；局部改动（期望正文里不少于一半的行原样出现在收到的正文里；二进制载荷没有行，按公共前缀和后缀合计不少于九成算）；其余是整页替换。只有局部改动算篡改。代理擅自加了 gzip 压缩而解开后内容相同的，不算内容被改，单独计数 |
| 中间人 | 隧道里握手拿到的证书不是 judge 的 |
| 请求被改、匿名程度 | 以 judge 记下的原始请求头为准。请求头里出现探测器的地址算透明，只暴露代理身份算匿名，都没有算高匿 |
| 重放 | 同一个 nonce 被 judge 收到不止一次 |
| 出口地址 | judge 日志里的对端地址。响应头里回显的地址只用来和日志互相核对 |
| 节点可用（严格） | 不管分享链接怎么写，按完整的证书校验连接节点，然后走完上面的全部阶段 |
| 节点可用（照链接） | 链接要求跳过证书校验、严格校验又连不上时，照链接的要求再试一次。只用来量化严格校验的代价，不作为可用的依据 |

出口地址、请求有没有被改、有没有重放，这三件事只以 judge 的记录为准，探测器自己的记录不作数。

## 频率与限速

| 项目 | 取值 |
| --- | --- |
| 每秒新建连接 | 最多 40 条 |
| 同时进行的探访 | 最多 300 个 |
| 同一个 IP | 同时只探访一个端口 |
| 同一个 /24 | 同时最多 4 个探访 |
| 可用的条目 | 每 20 分钟复测 |
| 连得上但不可用的条目 | 每 2 小时复测 |
| 连不上的条目 | 30 分钟起每次加倍，上限 6 小时；曾经可用的从 5 分钟起 |
| 下榜的条目 | 继续探测 24 小时 |
| 聚合器抽样 | 可用的每 60 分钟，连不上的每 6 小时 |
| 节点 | 每 60 分钟一轮；每轮先做 DNS 和 TCP 预检，连得上的再分批（每批 400 个）经 sing-box 探测。可用的节点每轮都测；不可用的隔 1、2、4、6 轮再测 |

不探测的地址：私网和保留地址段、judge 自己的地址、28 个不会有代理的知名端口（SSH、邮件、数据库等）、退出名单里的地址。
各类被排除的条目数记在运行状况记录里。

## 对照与自检

- 对照：每分钟不经任何代理直接访问 judge 一次（回环地址和公网地址各一次），每 5 分钟直接访问两个 IP 回显服务一次。
  回环对照失败的时段说明故障在我们自己这边，这些时段里代理的失败不算作“死亡”。
- 仪器自检：`fieldtest selftest` 在本机启动 judge、两个假的回显服务和 33 个代理夹具，其中有规矩的，也有注入脚本、
  替换广告 ID、剥离 https、冒充 TLS、假装成功、慢速、半开、要求认证、重放请求、返回缓存的。
  探测器按正式流程逐个探访，每一项判定都要与夹具的已知行为一致。节点探测用本机的 sing-box 服务端自检。
  预检时在测量用的机器上跑一遍；有任何一项不符，数据不可信。
- 不变量：TLS 校验通过的请求，judge 收到的必须与探测器发出的完全一致，TLS ClientHello 的指纹必须与直连时相同；
  探测器认为成功的请求，judge 的日志里必须有；节点探测的出口地址不能是本机。
  汇总时逐条核对，出现一次就说明仪器有错。
- 解析对端字节的代码（列表、分享链接、各协议的握手应答）都做了模糊测试；列表解析器与普查脚本逐个文件核对过，
  65 个文件、271 万个条目的结果完全相同。

| Mani 等，ACSAC 2018 | 107,034 个被列出的代理，50 天，每天探测一次 | 每天有回应的占每天列出的 | 中位数 3,283 / 41,520，约 8% |
| | | 明文 HTML 内容不符 | 10.5% 的请求；其中约 80% 无害，多为错误页；恶意的占全部 HTML 请求的 2.2% |
| | | 证书被替换 | 支持 HTTPS 的代理里 1.06%（102 / 9,625） |
| | | 请求头带出客户端地址 | 66.08%（9,079 / 13,740） |
| | | 把 https 链接改成 http | 没有发现 |
| Tsirantonakis 等，NDSS 2018 | 65,871 个 HTTP 代理，两个月，每天约 22 次 | TCP 连得上过 | 49,444 个 |
| | | 取回过测试页 | 19,473 个 |
| | | 改动了内容 | 7,441 个，占取回过测试页的 38%；其中恶意或不受欢迎的 1,004 个，占 5.15% |
| Mehanna 等，MADWeb 2024 | 640,600 个代理，30 个月，每天测试 | 至少活跃过一次 | 34.5% |

| 指标 | 预期范围 | 依据 |
| --- | --- | --- |
| 常规列表的时点可用率 | 5% 到 40% | 文献是 8% 到 35%；本次的列表多数由维护者自动筛过，应偏高 |
| 证书被替换的代理占可用隧道代理 | 0% 到 5% | Mani 等 1.06% |
| 明文正文不符的代理占能转发的代理 | 5% 到 40% | Mani 等按请求 10.5%，Tsirantonakis 等按代理 38%（含无害改动） |

| 请求头带出客户端地址的代理占能转发的代理 | 30% 到 80% | Mani 等 66% |

## 伦理与对他人的影响

- 只连接公开列表里的地址，不扫描网段。
- 低速：全局每秒不超过 40 条新连接，同一个 IP 同时只有一条。
- 除了访问自己的 judge 和两个公开的 IP 回显服务，不经这些代理发送任何流量。
- 不尝试任何用户名和密码。
- judge 的首页说明这是一项测量、怎样联系我们把地址排除。排除名单是数据目录下的 `exclude.txt`，改动后五分钟内生效。
- 记录里只有本来就公开的代理地址和我们自己的请求，没有任何第三方的流量。节点的凭据不写入记录。

## 已知局限

- 只有一个观测点。代理可能按来源地区区别对待，结论只对这个观测点成立。
- judge 与探测器同机。两者是独立的进程和日志，但不是独立的主机；judge 的机器出故障时两边会一起失效，靠对照记录识别。
- 诱饵站点不是真实站点。代理可能只对特定网站下手（Tsirantonakis 等观察到过），我们测到的篡改率是下限。
- 明文载荷只有 HTML、JavaScript 和二进制三种，不含可执行文件，所以看不到“给下载的程序打补丁”这类行为。
- 只测 IPv4，只测 TCP。
- 节点由 sing-box 1.14.4 连接。它不支持的传输方式（xhttp 等）和协议不在测量范围内，这些节点单独计数。
- 72 小时看不到按周变化的规律。
- 寿命的分辨率是 20 分钟；短于它的中断看不到。

## 记录

全部原始记录是按小时切分的 JSONL 文件，只追加不修改。

| 文件前缀 | 内容 |
| --- | --- |
| `probe-` | 每一次尝试（`att`）、每一次探访的小结（`visit`）、节点预检（`npre`）、每轮节点探测的小结（`nround`）、sing-box 报告的错误（`nerr`）、运行状况（`stat`） |
| `judge-` | judge 收到的每个探测请求（`req`，含原始请求头）、无关流量（`noise`）、失败的 TLS 握手（`tls_fail`） |
| `snap-` | 每次抓取列表的结果和增减的条目（`snap`）、聚合器抽样（`agg_sample`）、订阅快照（`nsnap`）、节点的描述（`node`，不含凭据） |
| `evidence/` | 按内容哈希存放的证据：被改的正文、不属于 judge 的证书链 |
