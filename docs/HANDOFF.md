## fieldtest 现状

- 版本 0.1.1-20261106。相对 0.1.0 只修了一处：探测器重启后汇总里的节点数会重复计数。
- 测试：`go test`（含仪器自检：33 个代理夹具、10 个节点用例、199 项核对）、三项模糊测试、
  端到端测试（`test/e2e.sh`，30 项核对）、竞态检测。CI 见 `.github/workflows/fieldtest.yml`。
- 构建可复现：同一份源码、同一个 Go 版本（1.24.7）、同一个 `VERSION`，二进制逐字节相同。
- 解析器与普查脚本对账过：65 个列表文件、271 万条目，逐文件一致；节点 21,532 个，去重结果一致。
  对账测试要普查数据，设置环境变量才运行（`FIELDTEST_HIST_DIR`、`FIELDTEST_NODES_DIR`），CI 里不跑。
  数据用 `research/census/fetch_history.sh` 重新抓，约 1.4 GB。

### 端到端测试里“看起来像问题、其实不是”的两处

- 预检一定报失败，汇总一定警告“直连第二观察者全部失败”：布景里的主机名
  （`judge.test`、`obs1.test`、`obs2.test`）只有夹具认得，本机解析不了。`test/e2e.sh` 和 `e2e_check.py` 已经考虑了这一点。
- 节点探测的轮次编号在重启后从 1 重新开始。只是显示上的事，没有修。

### 写这个工具时踩过的坑

改相关代码前先看一眼，免得重犯：

- judge 的日志 2 秒落盘一次。汇总在对账时要留 10 秒余量，否则会误报“judge 没收到”。
- 聚合器抽样只抽一次，抽样结果存在状态文件里。重启后重抽会让样本不可比。
- 被 sslstrip 改写的页面要按行相似度归类（`Sim`），只比前后缀会归错类。
- vmess 链接的 JSON 后面跟着多余数据要拒收；端口按第一个冒号切分。少了这两条，节点数与普查对不上。
- systemd unit 里不能同时用空的 `CapabilityBoundingSet` 和文件 capability（会 EPERM）；
  `NoNewPrivileges` 会丢掉文件 capability。`setcap` 只在 systemd 低于 229 时才用。
- 判断有没有 systemd 看 `/run/systemd/system`，不看有没有 `systemctl` 命令。
- 抓空列表文件偶尔返回 5xx：出错或 5xx 时重试一次。
- 候选对象的字段会被多个 goroutine 读写，统一经 `Pool.With` 访问。
- 限速器的等待时间不算进一次尝试的耗时。

## 工程约束

- 写代码的云端工作区出口有白名单：GitHub（含 raw 和 release）、npm、PyPI、crates.io 能访问；
  **Go 的模块代理（proxy.golang.org、sum.golang.org）和 go.dev 不能访问，用户的服务器也不能访问。**
  所以 fieldtest 只用标准库，部署由用户在服务器上执行。新会话的出口策略可能不同，先试一下再定。
- 到实现网关、要嵌入 sing-box 时，依赖的来源有三条路：从 GitHub 上的镜像仓库取、让用户放行这两个域名、交给 CI 构建。
  GitHub Actions 的 runner 没有这个限制，CI 构建这条路最可能走通。
- 遇到出口策略拒绝，不要换工具绕过，直接告诉用户。
